## Результаты

### 1. Проверка путей

- **Доказательство:** `src/voicecontrol/commands/builtins.py:26-36` использует `Path.resolve()` и `is_relative_to()`; `:82-120` требует абсолютный путь, отклоняет `..` и проверяет разрешенные директории.
- **Проверенные тесты:** `tests/test_builtins.py:40-63` покрывает путь вне allowed directory, относительный путь и `..`; `tests/test_os_handlers.py:125-142` покрывает отказ для внешнего каталога и traversal.
- **Репродукция:** тест `test_traversal_refused` передает путь с `..`; обработчик должен вернуть отказ, а subprocess не должен вызываться. Тест есть в проекте и вошел в выполненный полный набор.
- **Severity:** Low (неподтвержденный риск/неполнота тестов).
- **Статус:** частично проверено. В коде есть нормализация и проверка границ; отдельных тестов symlink/junction и mixed-slash путей не найдено. Их отсутствие не доказывает обход.
- **Рекомендация:** добавить Windows-тесты для symlink/junction и смешанных разделителей, включая отказ при ссылке за пределы base. Учитывать ограничения прав на создание ссылок в CI.

### 2. Запуск процессов и shell

- **Доказательство:** единственный вызов `subprocess.run()` в `src` находится в `src/voicecontrol/platform_adapter.py:47-54`; передаются argv-список и `shell=False`. Прямое выполнение произвольных команд отключено в `commands/command_handler.py`.
- **Проверенные тесты:** `tests/test_platform_adapter.py:48-59,77-89` проверяет argv, `shell=False` и отсутствие `shell=True`; `tests/test_command_handler_disabled.py` проверяет, что отключенный handler не вызывает subprocess и что запрещенные API не используются.
- **Репродукция:** тест `test_success_with_zero_returncode` проверяет аргументы вызова; AST-тест анализирует модуль адаптера на `shell=True`.
- **Severity:** Не установлена.
- **Статус:** проверено статическим просмотром текущего `src` и указанными тестами; системные команды не запускались реально.
- **Рекомендация:** сохранять единый шлюз запуска процессов, список аргументов и `shell=False`; повторять поиск по всему `src` при добавлении новых интеграций.

### 3. Whitelist приложений и аргументы

- **Доказательство:** `src/voicecontrol/commands/os_handlers.py:44-55` разрешает имя только через `security.app_whitelist`; неизвестное приложение отклоняется. Путь запуска берется из конфигурации, а не из распознанного текста.
- **Проверенные тесты:** `tests/test_os_handlers.py:78-99` проверяет отказ для неизвестного приложения и разрешение имени из whitelist.
- **Репродукция:** отправить `открой страшный вирус` при пустом для него whitelist; ожидать отказ и отсутствие вызова `subprocess.run`. Этот случай покрыт тестом `test_unknown_app_never_executes`.
- **Severity:** Не установлена.
- **Статус:** проверено в пределах обработчиков и тестов; корректность содержимого пользовательского whitelist и поведения каждой внешней программы не проверялась.
- **Рекомендация:** продолжать валидировать конфигурацию whitelist и не добавлять обработчики, использующие имя приложения непосредственно из текста команды.

### 4. `dry_run`

- **Доказательство:** `platform_adapter.py:34-44` прекращает выполнение до subprocess при `dry_run=True`; конструкторы адаптеров и фабрика имеют `True` по умолчанию (`:82`, `:147`, `:185`, `:228`). `commands/os_handlers.py:74` передает параметр из конфигурации с fallback `True`.
- **Важно:** `run_command()` требует явный keyword-only аргумент `dry_run`; у него нет собственного значения по умолчанию.
- **Проверенные тесты:** `tests/test_platform_adapter.py:37-45` проверяет отсутствие вызова subprocess при dry-run; `tests/test_os_handlers.py:154-163` проверяет dry-run для подтвержденного выключения.
- **Severity:** Не установлена.
- **Статус:** базовое поведение и несколько путей проверены. Исчерпывающее покрытие всех платформенных обработчиков не заявляется.
- **Рекомендация:** для новых обработчиков добавить тест, подтверждающий, что dry-run не выполняет действие; реальное выполнение тестировать только через моки.

### 5. Ошибки и раскрытие подробностей

- **Доказательство:** `platform_adapter.py:28-29,57-74` предоставляет только `success` и строку `detail`; stderr/stdout и некоторые сообщения исключений включаются в результат. `commands/os_handlers.py:20-25` включает `detail` в текст результата при ошибке.
- **Репродукция:** замокать `subprocess.run()` результатом с `stderr`, содержащим тестовый локальный путь; проверить, что деталь попадает в `ActionOutcome` и формируемое сообщение обработчика.
- **Severity:** Low — диагностические сведения могут раскрыть локальные пути или подробности ОС вызывающему коду.
- **Статус:** поведение подтверждено просмотром кода; отдельного теста на редактирование/утечку подробностей нет.
- **Рекомендация:** определить модель публичных ошибок, исключить секреты и избыточные локальные сведения из пользовательского сообщения; при необходимости добавить структурированный код ошибки, сохраняя подробности только в защищенном логе.

### 6. Полнота аудита и готовность приложения

- **Доказательство:** `audio/listener.py:52-59` выбрасывает `NotImplementedError` при ожидании wake phrase; `speech/recognizer.py:16-43` возвращает случайный демонстрационный текст; `main.py:66-73` блокирует production-режим.
- **Severity:** Не security-уязвимость; существенный функциональный блокер.
- **Статус:** подтверждено просмотром кода. Полный микрофонный/STT сценарий интеграционно не выполнялся.
- **Рекомендация:** не заявлять production-ready состояние до реализации wake phrase и реального STT, а также прохождения интеграционных тестов.

## Неточности предыдущего отчета

- Утверждение о чистом `master` не подтверждено: рабочее дерево содержит изменения.
- Проверка пути находится в валидаторах команд, не в `run_command`.
- У `run_command()` нет значения `dry_run=True` по умолчанию, хотя адаптеры и фабрика имеют безопасное значение по умолчанию.
- Утверждение, что детали ошибок не возвращаются вызывающему коду, неверно.
- Утверждение о production-ready состоянии не подтверждается: wake phrase и реальное распознавание речи не реализованы.
- Наличие `Path.resolve()`/`is_relative_to()` и успешных тестов `..` не означает, что все сценарии symlink/junction уже проверены.

## Итог

В проверенном коде не подтверждена уязвимость обхода shell или прямого запуска произвольного текста команды: вызов процесса централизован, использует список аргументов и `shell=False`, а запуск приложений ограничен whitelist. Это ограниченный вывод по просмотренному коду, а не гарантия отсутствия уязвимостей.

Остаются непроверенные сценарии ссылок и платформенного поведения, а также риск передачи подробностей ОС через строковый `detail`. Проект не следует считать production-ready до завершения голосового сценария и дополнительной проверки на целевых ОС.
