# VoiceControl Agent — актуальные задачи

Обновлено: 2026-11-01. Этот документ отражает проверенное состояние репозитория, а не предположения из прежнего аудита.

## Подтвержденное состояние

| Область | Текущее состояние | Что еще требуется |
|---|---|---|
| Аудиозапись | `AudioListener.record_command()` использует `Microphone` и `VoiceActivityDetector`; есть ограничение длительности и завершение по тишине. | Добавить автоматические тесты цикла записи и поведения при ошибках устройства. |
| Wake phrase | `wait_for_wake_phrase()` в `audio/listener.py` выбрасывает `NotImplementedError`. `WakeWordDetector` ищет фразу в тексте, но не интегрирован с аудиопотоком. | Реализовать сквозное ожидание ключевой фразы и подключить его к основному циклу. |
| Распознавание речи | `SpeechRecognizer` возвращает случайную демонстрационную фразу; реального STT нет. | Подключить реальный выбранный backend, корректно обрабатывать отсутствие модели/ошибки и исключить фиктивные результаты. |
| Production-запуск | `main.py` блокирует `run_mode != "test"`. | Снимать блокировку только после реализации и проверки реального wake phrase, STT и полного безопасного сценария. |
| Проверка путей | Валидатор в `commands/builtins.py` проверяет абсолютный путь, запрещает `..`, использует `resolve()` и `is_relative_to()`. Тесты уже покрывают traversal и выход за разрешенную директорию. | Добавить тесты symlink/junction и смешанных Windows-разделителей. |
| Запуск ОС-команд | В `src` обнаружен единый `subprocess.run()` с argv-списком и `shell=False`; запуск приложений разрешается через whitelist. | Сохранять единый шлюз выполнения и проверять аргументы всех новых действий. |
| Безопасный режим | Адаптеры и фабрика по умолчанию используют `dry_run=True`; `build_os_registry()` берет настройку из конфига с fallback `True`. `run_command()` требует явный `dry_run`. | Проверить тестами конфигурационные пути и каждый добавляемый обработчик, не полагаясь на несуществующий default у `run_command()`. |
| Ошибки | `ActionOutcome` содержит только `success` и `detail`; подробности процесса могут передаваться вызывающему коду. | Решить, нужны ли структурированные коды ошибок и редактирование чувствительных подробностей. |
| Проверка проекта | `python -m pytest`: 153 теста прошли, есть одно предупреждение `comtypes` на Python 3.15. | Отдельно выполнить нужные статические проверки и тесты по поддерживаемым версиям Python; они не запускались в этой проверке. |

## Задачи

1. **Реализовать сквозное обнаружение wake phrase**
   - Подключить выбранный механизм к аудиовводу; не считать поиск фразы в уже готовом тексте обнаружением по микрофону.
   - Обеспечить остановку/закрытие ресурсов и контролируемое поведение при недоступном микрофоне.
   - Добавить тесты на обнаружение, пропуск фоновой речи, остановку и ошибки.

2. **Заменить демонстрационный распознаватель**
   - Подключить реальный STT backend с настройкой модели/языка и явным поведением при отсутствии зависимости или модели.
   - Не возвращать случайную команду при ошибке или пустом распознавании.
   - Покрыть успешный результат, пустой ввод и ошибки тестами с подмененным backend.

3. **Проверить интеграцию голосового сценария**
   - Добавить тесты от wake phrase через запись и распознавание до диспетчеризации.
   - Проверить, что тестовые компоненты включаются явно и production не запускается до готовности реального сценария.

4. **Расширить тесты валидации путей**
   - Сохранить существующие проверки `..` и выхода за разрешенную директорию.
   - Добавить сценарии symlink/junction, указывающих за пределы разрешенной директории, и mixed-slash путей на Windows.
   - Если создание ссылки недоступно в среде тестирования, явно пометить такой тест как пропущенный с причиной, а не считать его пройденным.

5. **Уточнить контракт ошибок и безопасного режима**
   - Решить, нужны ли `ActionOutcome` структурированные коды вместо одного `detail`.
   - Проверить, какие детали subprocess-ошибок доходят до пользовательских сообщений, и при необходимости редактировать локальные пути/системные подробности.
   - При добавлении новых действий проверять, что default остается dry-run и реальное выполнение возможно только через явно заданную конфигурацию.

6. **Согласовать поддержку Python**
   - Сверить комментарии и документацию с `requires-python = ">=3.11"`.
   - Проверить совместимость на заявленных версиях либо сузить/уточнить заявленную поддержку на основании фактических тестов.

## Критерий готовности

Не объявлять приложение production-ready, пока wake phrase и STT не работают без имитаций, полный голосовой сценарий не покрыт тестами, а известные ограничения платформенной валидации не задокументированы. Текущий результат `pytest` подтверждает только прохождение имеющегося набора тестов.
